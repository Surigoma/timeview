# TimeView 仕様書

- 作成日: 2026-09-19
- バージョン: 0.9
- 状態: 初期実装の基準仕様（実装・検証状況はVALIDATION.mdを参照）
- 仮称: TimeView
- 確定要件: TIME-PONを参考に新しいタイマーを作成する。バックエンドはGo、フロントエンドはReact。外部APIおよびKeypad入力に対応する。ルーム機能は設けず、単一タイマーとする。Windows・macOS・Linuxに対応する。SQLite等のDBは使用せず、タイマー状態はメモリ、再利用する設定はJSONファイルで管理する。
- 運用要件: オフラインかつ分離ネットワークで使用する。認証・権限管理およびTLSは実装せず、HTTPで操作・表示・API通信を行う。
- 開発要件: タスクランナーにはTask（go-task）を使用する。
- 本書の位置付け: 確定要件以外の数値、画面構成、操作割り当ては実装に向けた提案。既存TIME-PONを操作するコントローラーや互換APIの開発ではない。

## 1. 目的と利用シーン

上映イベント、カンファレンス、講演で、オペレーターが残り時間とカンペを管理する。演台には表示専用画面を配置し、別PC・同一PCの操作画面、USBテンキー、HTTP対応の外部機器から制御する。上映中は表示専用画面を暗転できる。

会場内LANだけで動作し、通常運用ではインターネット接続を必要としない。サーバーはWindows・macOS・Linuxで動作し、操作・表示はブラウザで行う。1つのサーバープロセスが1つのタイマーを管理し、複数の操作端末・演台端末は同じ状態を共有する。

### 1.1 参考元と新規設計の区別

TIME-PONの公開READMEから、演台表示と操作画面の分離、カウントダウン、2段階警告、カンペ、開始・一時停止・リセットを参考にする。公開PHPコードには開始・停止等を受け付ける処理があるが、本システムでは独立したJSON APIを設計する。

参考資料（確認日: 2026-09-19、mainブランチ。固定リビジョンではない）:

- [TIME-PON README](https://github.com/pondashicom/timepon#readme)
- [TIME-PON index.php](https://github.com/pondashicom/timepon/blob/main/index.php)
- [TIME-PON LICENSE.txt](https://github.com/pondashicom/timepon/blob/main/LICENSE.txt)

以降に記載するAPI、保存方式、Keypad割り当て、障害時の動作はTimeView独自の提案仕様であり、TIME-PONの既存仕様を示すものではない。参考コード等を転用する場合は、同梱ライセンスの表示条件を確認して対応する。

## 2. 初期リリースの範囲

| 区分 | 初期リリースに含める内容 |
| --- | --- |
| 管理単位 | サーバーあたりタイマー1つ。ルームの作成・選択・削除やIDは不要 |
| タイマー | 持ち時間、開始、停止、再開、リセット、残り時間の加減算 |
| 警告 | 残り時間に応じた2段階警告と時間超過表示 |
| 演台表示 | 大きな時間表示、カンペ、全画面、接続状態 |
| 画面暗転 | すべての演台画面を黒一色にする。操作画面・API・Keypadから暗転／解除 |
| 操作画面 | 単一タイマーの操作、表示プレビュー |
| カンペ | 自由文、定型文、表示・非表示、消去 |
| 外部操作 | HTTP JSON API、状態取得、SSEによる状態配信 |
| 操作元制限 | 設定により変更操作を同一オリジンのブラウザ画面・Keypadだけに限定 |
| Keypad | キーボードとして認識されるUSBテンキー等の入力、キー割り当て変更 |
| 状態管理 | 残り時間等の実行状態はメモリに保持。設定、定型文、Keypad割り当てはJSONへ保存 |
| 配布 | React成果物を埋め込んだ各OS向けGo実行ファイル。DB・データディレクトリ不要 |

初期リリースには、OS全体のグローバルキー取得、専用USBドライバー、シリアル接続、MIDI、OSC、Art-Net、外部サービス連携、専用Stream Deckプラグイン、タイムテーブル自動進行、クラウド同期を含めない。HTTPを送信できる機器・ソフトは共通APIから利用できるが、機種別の動作保証は実機確認後とする。

## 3. システム構成

```text
USB Keypad → React操作画面 ─┐
React画面の操作ボタン ─────┼─ HTTP JSON API → Go（タイマーはメモリ、設定はJSON）
外部機器・制御ソフト ──────┘                    │
                                               └─ SSE → 操作画面／演台画面
```

| 要素 | 採用案 | 役割 |
| --- | --- | --- |
| サーバー | Go + Gin | ルーティング、ミドルウェア、JSON応答、静的ファイル配信、状態配信 |
| UI | React + TypeScript + Vite | 操作画面・演台画面。CSSでレイアウト |
| 状態管理 | Goの構造体・map・sync.Mutex | タイマー状態と再送抑止情報をメモリ内で一括更新 |
| 設定保存 | Koanf + UTF-8 JSONファイル | 設定、定型文、Keypad割り当てをDBなしで保存 |
| 入力検証 | go-playground/validator | 設定ファイルとKeypad割り当ての宣言的な検証 |
| 流量制限 | golang.org/x/time/rate | APIクライアント単位のトークンバケット制御 |
| 配信 | Server-Sent Events（SSE） | サーバーからブラウザへ最新状態を配信 |
| 配布 | Go embed | 本番はNode.js不要。ビルド時のみフロント用ツールが必要 |
| タスクランナー | Task（go-task） | 開発・検証・ビルド・配布用コマンドをTaskfile.ymlに集約 |

単一プロセスで開始する。SQLite、Redis、メッセージブローカーは導入しない。HTTPの定型処理はGin、JSON設定の変換はKoanf、構造体検証はvalidator、流量制限はx/time/rateへ任せる。タイマーの状態遷移、同時実行制御、再送抑止、設定ファイルの原子的置換は製品固有の処理として実装する。CGOやOS専用APIへの依存を避け、依存バージョンは`go.mod`と`go.sum`で固定する。

画面操作も外部操作も同一のコマンド処理を通す。状態の検証・変更・再送抑止記録を同じロック内で行い、成功後に応答・配信する。通信処理はロック外で行う。DB用の抽象層や移行機構は用意しない。

## 4. 画面仕様

### 4.1 操作画面 `/`（`/control`も同じ画面）

- 起動後は操作画面を直接開く。残り時間、状態、演台表示のプレビューを表示する。
- 演台画面と設定画面を開く操作を用意する。
- 開始／再開、一時停止、リセット、+1分、-1分を用意する。
- 「暗転」「暗転解除」を別々のボタンとして配置する。操作画面は暗転せず、現在の暗転状態と残り時間を常時確認できる。プレビューは演台と同じ黒表示にし、その外側に「暗転中」を表示する。
- 持ち時間、警告時間、色、時間切れ点滅、ブラウザ操作限定、カンペを設定する。
- カンペの入力・送信、非表示、再表示、消去、最大9件の定型文を用意する。
- API連携用にエンドポイントのコピー機能を用意する。
- Keypadの有効状態、割り当て、最後の入力結果を常時確認できる。
- 設定・定型文・Keypad割り当てはJSONへ保存され、実行状態は再起動で初期化されることを設定画面に明示する。
- 接続中／再接続中／未接続を表示する。操作失敗は日本語で通知する。
- 未送信のカンペ入力と送信済みカンペを区別する。
- 実行中のリセットは画面ボタンで確認する。Keypadには別途誤操作対策を設ける。

### 4.2 タッチ操作画面 `/touch`

- 司会者がタッチパネルから操作するため、タイマー、開始／一時停止、±1分、リセット、暗転、カンペ表示、定型文を一画面に配置する。
- タップ対象は通常の操作画面より大きくし、横長・縦長の画面では一列または二列に収める。
- 実行中のリセットでは通常の操作画面と同じ確認を行う。
- 設定編集とKeypad割り当ては設けず、通常の操作画面への導線を表示する。

### 4.3 演台画面 `/display`

- 操作部品を極力省き、残り時間とカンペを大きく表示する。
- 横長・縦長の画面に追従し、時間表示が領域からはみ出さないよう縮小する。
- 表示モードは「タイマーのみ」「タイマー＋カンペ」「カンペのみ」。モードはすべての演台画面に同期する。
- 演台画面には「待機中」「計測中」「一時停止」「時間超過」等の状態文字を表示しない。状態は操作画面で確認する。
- 残り時間の段階に応じて背景全体を通常色、第1警告色、第2警告色、時間超過色へ切り替える。時間とカンペの文字色は背景から白または黒を自動選択する。
- 画面下部に経過時間ゲージを表示する。ゲージ全体を通常・第1警告・第2警告の設定色で区切り、斜線の経過領域と現在位置を重ねる。直上に「第1警告まで 07:00」「第2警告まで 01:50」「終了まで 00:30」のように次の境界までの時間を表示する。無効値0の警告領域は表示しない。経過率は`(持ち時間 - 残り時間) / 持ち時間`を0～100%へ制限し、時間超過時は100%、残り時間加算で持ち時間を超えた場合は0%とする。
- 全画面への切り替えは画面内ボタンから行う。
- 通信断中は推定表示であることを示す小さな警告を出す。ただし暗転中は警告も表示しない。
- 通常のカンペはプレーンテキストとして表示し、HTMLは解釈しない。

### 4.4 設定画面 `/settings`

表示URLの確認・コピー、Keypad割り当て、表示言語、システムログレベルの設定を行う。表示言語は日本語と英語から選び、設定保存後に接続中の全画面へ同期する。ログレベルは `debug`、`info`、`warn`、`error` から選び、保存と同時に稼働中のプロセスへ反映する。APIと画面の操作失敗メッセージは運用時の照合を優先して日本語のままとする。待受アドレスとポート、JSON設定ファイルの保存先は起動オプションで指定できる。

### 4.5 操作ログ画面 `/logs`

- 起動、正常終了、異常終了と変更操作の成否を一覧表示する。
- 最新500件を新しい順に表示し、手動で再読込できる。
- カンペ本文、設定値、要求本文は表示・記録せず、操作種別と結果だけを扱う。

### 4.6 画面暗転（上映用）

- サーバーに真偽値`blackout`を持ち、接続しているすべての演台画面に同期する。端末別の暗転は初回の対象外。
- `blackout=true`では演台画面の描画領域全体を`#000000`で塗り、時間、カンペ、警告色、点滅、接続通知、ボタン、アプリ内カーソルを表示しない。全表示モードより暗転を優先する。
- 暗転と解除では時間、カンペ、ゲージ、通知、ボタン、カーソルを即時に非表示／再表示する。背景色は見た目を滑らかにするため180ms程度の短いフェードを許可する。暗転中のクリック・タップ・マウス移動では解除しない。解除は操作画面・API・Keypadから明示的に行う。
- 暗転は表示だけに作用する。実行中の計測は続け、一時停止中なら停止を維持する。時間切れやカンペ送信、start、pause、reset、表示モード変更で自動解除しない。
- 暗転中もカンペや設定を更新できる。解除すると、その時点の残り時間・警告・表示モード・カンペ表示フラグを反映する。暗転前のスナップショットには戻さない。
- サーバー起動・再起動時は`blackout=true`を既定とする。上映中の意図しない点灯を避け、設定確認後にオペレーターが解除する。
- 演台ページの初期HTMLと読み込み中の背景も黒とし、サーバーの最新状態を受信するまでコンテンツを出さない。通信断中は最後に受信した暗転状態を維持し、暗転中の再接続で一瞬コンテンツを表示しない。
- 演台ページで状態取得・再接続に失敗しても、エラーページへ自動遷移しない。初回取得前または暗転中は黒表示を維持する。再起動通知は操作画面側だけに表示する。
- 暗転APIの成功はサーバー状態の更新を意味し、すべての端末への描画完了を保証しない。未接続端末へは届かず、再接続後に最新状態を反映する。上映開始前に実際の表示を確認する。
- 対象はTimeViewの演台ページ。上映時は全画面表示を使用する。OS通知・ブラウザUI・他アプリやディスプレイ電源、プロジェクターのシャッターは制御しない。機器自体の黒レベルやバックライトによる発光は残り得る。

## 5. タイマー仕様

### 5.1 値と状態

- 持ち時間: 1秒～24時間。UIは時・分・秒で入力、APIは整数秒。
- 既定値: 持ち時間600秒、第1警告180秒、第2警告60秒。
- 状態: `idle`（待機）、`running`（計測中）、`paused`（停止中）。
- 時間切れは独立した動作状態ではなく、残り時間が0以下という表示条件。
- `running`では時間切れ後も計測を続け、負の残り時間で超過量を表す。
- 内部計算はミリ秒。APIの残り時間も符号付きミリ秒で返す。

### 5.2 コマンドと状態遷移

| コマンド | idle | running | paused |
| --- | --- | --- | --- |
| start | 現在の残り時間から開始 | 成功・変更なし | 現在の残り時間から再開 |
| pause | 成功・変更なし | その瞬間の残り時間で停止 | 成功・変更なし |
| reset | 持ち時間へ戻す | 停止し、持ち時間へ戻す | 持ち時間へ戻す |
| adjust | 待機中の残り時間を加減算 | 計測を維持して加減算 | 停止を維持して加減算 |

`reset`後の状態は常に`idle`。カンペ・表示モード・警告設定・暗転状態には影響しない。カンペ消去と暗転解除は独立した操作とする。

`adjust`は設定済みの持ち時間を変更しない。例えば持ち時間10分、残り5分で+1分を実行すると残り6分になり、後からresetすると10分に戻る。加減算は1回あたり±3600秒以内の非ゼロ整数とする。時間の減算で0を下回ることを許可する。操作で残り時間が±24時間を超える場合は422にする。自然経過による超過時間はこの制限で停止しない。

持ち時間の変更は`idle`のみ許可し、残り時間も新しい持ち時間にそろえる。`running`または`paused`での変更は409。警告時間と色、表示モードはどの状態でも変更できる。

### 5.3 警告・時間表示

警告は残り時間を基準とする。設定条件は `0 <= 第2警告 <= 第1警告 <= 持ち時間`。0秒指定の警告は無効。同値の場合は第2警告を優先する。持ち時間変更で条件を満たさなくなる場合は、警告値も同じ更新で修正するか422とする。

| 条件（上から優先） | 既定表示 |
| --- | --- |
| 残り時間 <= 0 | 赤系背景（既定`#ff6069`） |
| 第2警告が有効かつ残り時間 <= 第2警告 | オレンジ背景（既定`#ff9854`） |
| 第1警告が有効かつ残り時間 <= 第1警告 | 黄色背景（既定`#f2cc60`） |
| 上記以外 | グレー背景（既定`#4b5263`） |

時間切れ点滅は既定でOFF。ONでも緩やかな明暗変化とし、OSの動きを抑える設定を尊重する。警告音は初期対象外。

正の残り時間は秒未満を切り上げる。超過時間は絶対値の秒未満を切り捨て、1秒以上の超過からマイナスを付ける。時間切れ直後の1秒未満は`00:00`と時間超過表示にする。1時間未満は`MM:SS`、1時間以上は`H:MM:SS`。警告判定は丸める前の値で行う。

### 5.4 時間管理と復旧

- Go側を正とし、毎秒1ずつ減算せず、計測基準点と経過時間から残り時間を算出する。
- 稼働中の経過時間はGoの単調増加時計を利用し、OSの時刻補正による急なジャンプを避ける。
- API応答・SSEには、その時点の`remainingMs`、`state`、`serverTimeMs`、`instanceId`、`version`を含める。`instanceId`は起動ごとに生成するランダムID。
- Reactは受信時の値を基準に単調増加時計で補間し、次のサーバー情報で補正する。一定周期の減算値を正として保存しない。
- 通信遅延の補正には状態取得の往復時間を使う。同期精度は会場LANでの受入試験で確認する。
- 通常の状態配信は1秒間隔。操作成功時は直ちに配信する。
- 5秒間、新しい状態を受信できなければ通信断表示にする。暗転中の演台画面には通知を出さない。実行中ならローカル推定を継続し、操作は無効化する。
- 再接続時は最新スナップショットで置換する。通信断中の操作をキューに溜めて後で自動実行しない。
- サーバー終了・クラッシュ・再起動では実行状態を破棄する。次回起動は保存済みの持ち時間、警告、配色、点滅、表示モード、表示言語、定型文、Keypad割り当てを復元する。残り時間は持ち時間へ戻し、`idle`、カンペなし、`blackout=true`から開始する。以前の計測を復元・自動再開しない。
- 再起動後は同じURLへ自動再接続する。新しい`instanceId`を受け取った画面は旧状態と未完了要求を破棄する。操作画面には「サーバーが再起動し、初期化されました」と表示し、演台画面は暗転を優先する。`version`の大小比較は同じ`instanceId`内でのみ行う。
- サーバーPCのスリープは通常運用外。復帰後は再同期・状態確認を行う。スリープ中の表示同期は保証しない。

## 6. カンペ仕様

- 最大500 Unicodeコードポイント、改行を許可する。過長入力は切り詰めず422で拒否する。
- 空文字の送信は消去として扱い、`visible=false`にする。
- 非空文字の送信は本文更新と`visible=true`を一括で行う。
- 非表示は本文を保持する。再表示は保持した本文を表示する。本文が空の場合の再表示は422。
- 消去は本文を空にし、非表示にする。
- 定型文は最大9件、各500文字以内。押すと即時送信する。
- 表示しきれない場合は文字サイズを所定の最小値まで縮小する。なお収まらない文面は操作画面で警告し、短く編集できるようにする。

## 7. Keypad入力仕様

### 7.1 対応方式と制限

通常のキーボードイベントを送るUSBテンキー・プログラマブルKeypadを対象とする。ドライバーやWebUSBは使わず、React操作画面の`keydown`からAPIを呼び出す。

入力は対象の操作画面が前面にあり、フォーカスを持ち、Keypad操作が有効なときにのみ受け付ける。他アプリ操作中やブラウザを最小化した状態では反応しない。常時操作が必要な機器はHTTP API方式を使う。

ブラウザでは複数の物理キーボードを識別しない。同じキーコードは同じ操作となる。Num Lockによる違いや機種固有のコードはキー登録画面で実測する。

### 7.2 既定割り当て案

| キー | 操作 |
| --- | --- |
| NumpadEnter | 開始／再開 |
| NumpadDecimal | 一時停止 |
| NumpadAdd | 残り時間 +60秒 |
| NumpadSubtract | 残り時間 -60秒 |
| Ctrl + Numpad0 | リセット |
| Numpad1～Numpad9 | 定型文1～9を送信 |
| Numpad0 | カンペ非表示 |
| NumpadMultiply | カンペ再表示 |
| NumpadDivide | カンペ消去 |
| Ctrl + NumpadSubtract | 暗転 |
| Ctrl + NumpadAdd | 暗転解除 |

開始と停止は独立したキーにし、再送や連打で状態が反転するトグル操作を初期仕様に設けない。

暗転と解除も独立したキーにする。修飾キーを含め完全一致で判定し、Ctrl付きの暗転操作が残り時間の加減算としても実行されることを防ぐ。

### 7.3 入力処理

- `KeyboardEvent.code`と修飾キーで照合し、登録操作で変更できる。
- `event.repeat`、IME変換中、入力欄・テキストエリア・編集可能領域への入力は無視する。
- 登録したキーに対してのみブラウザ既定操作を抑止する。
- Keypadは初期OFF。明示的にONにすると有効状態を強調表示する。
- ページ遷移、タブ非表示、ウィンドウのフォーカス喪失、通信断でOFFに戻す。
- 同一キーの300ms以内の重複入力を無視し、操作送信中は新しいKeypadコマンドを受け付けない。
- 割り当て競合は保存時に拒否する。リセットには修飾キーを必須とする。
- 割り当てはサーバーのJSON設定へ保存し、すべての操作画面で共有する。ページ再読み込みとサーバー再起動後に復元する。Keypadの有効状態は保存せず、各画面で常にOFFから始める。
- Windows・macOS・Linuxそれぞれでキーコード・修飾キーを確認する。macOSでも既定のリセットはControlキーを使い、Commandキーへの変更は登録画面で行う。
- ブラウザ予約キーや機種固有入力をすべて捕捉できる保証はしない。選定実機で受入確認する。

## 8. 外部API仕様

### 8.1 共通規則

- ベースパス: `/api/v1`。JSON、UTF-8。
- すべてのAPIは認証なしのHTTPで利用する。Authorizationヘッダー、APIキー、Cookieは不要。
- 変更処理はPOST／PATCH／PUT／DELETEを使う。GETでは状態を変更しない。
- 秒・ミリ秒の単位をフィールド名で明示する。
- 未知フィールド、型違い、範囲外の値は拒否する。リクエスト本文上限は16KiB。
- 時間差で残り時間が変わっても`version`は増やさず、状態・設定の変更時に増やす。起動時は0から開始する。
- 部分的に変更して失敗することはない。各リクエストは原子的に実行する。
- 任意の`X-Timeview-Instance`ヘッダーに取得済みの`instanceId`を指定できる。再起動で不一致になった場合は409とし、操作しない。Reactからの変更要求には必ず付ける。
- `browserOnly=true`ではGETとSSEを引き続き公開し、変更要求だけを同一オリジンのTimeView操作画面とKeypadに限定する。画面は`X-Timeview-Client: browser`を付け、サーバーはブラウザが付与する`Sec-Fetch-Site: same-origin`との両方を確認する。条件を満たさない変更要求は403 `BROWSER_ONLY`とし、状態や再送記録を変更しない。
- 操作元制限は分離LAN内の誤操作防止であり、認証ではない。HTTPクライアントは同じヘッダーを模倣できるため、悪意ある端末への防御には使用しない。操作画面を利用できない場合は、サーバー停止中にJSON設定の`browserOnly`を`false`へ戻す。

### 8.2 エンドポイント

| Method | パス | 用途 |
| --- | --- | --- |
| GET | `/health` | プロセス稼働確認 |
| GET / PATCH | `/timer` | 状態取得／設定変更 |
| POST | `/timer/commands` | start、pause、reset、adjust |
| PUT | `/timer/blackout` | `{"enabled":true}`で暗転、`{"enabled":false}`で解除 |
| PUT | `/timer/message` | 本文と表示フラグの更新 |
| DELETE | `/timer/message` | カンペ消去 |
| GET / PUT | `/timer/presets` | 定型文一覧／一括更新 |
| GET / PUT | `/timer/bindings` | Keypad割り当て一覧／一括更新 |
| GET | `/timer/events` | 状態のSSE配信 |
| GET | `/logs` | 操作・プロセスログの最新500件 |

操作画面と演台画面は同じ状態取得APIとSSEを利用する。演台画面には操作UIを設けない。操作元制限が無効なら変更APIも送信元を区別せず、有効ならブラウザ要求情報を確認する。タイマーの作成・削除APIは設けず、起動時から1つ存在する。

### 8.3 コマンド例

```http
POST /api/v1/timer/commands
Content-Type: application/json
Idempotency-Key: <UNIQUE_REQUEST_ID>

{"command":"adjust","deltaSeconds":60}
```

開始・一時停止・リセットは、それぞれ `{"command":"start"}`、`{"command":"pause"}`、`{"command":"reset"}` を送る。

暗転は`PUT /api/v1/timer/blackout`へ`{"enabled":true}`、解除は`{"enabled":false}`を送る。`enabled`は必須のbooleanで、省略・null・文字列は422。同じ値を繰り返し指定しても反転せず、変更がなければ`version`を増やさない。成功時は200と最新状態を返し、変更時はSSEへ即時配信する。`Idempotency-Key`と任意の`If-Match`は共通規則を適用する。`PATCH /timer`での暗転変更は受け付けず、この専用APIへ集約する。

成功時は200と最新状態を返す。例:

```json
{
  "instanceId": "boot_abc123",
  "version": 12,
  "state": "running",
  "durationSeconds": 600,
  "remainingMs": 359800,
  "serverTimeMs": 1789776000000,
  "warning1Seconds": 180,
  "warning2Seconds": 60,
  "message": {"text": "まとめをお願いします", "visible": true},
  "displayMode": "timer_and_message",
  "language": "ja",
  "logLevel": "info",
  "blackout": true
}
```

### 8.4 再送・競合

- `adjust`では`Idempotency-Key`を必須とし、すべての変更APIで利用可能にする。UIは全変更操作に付ける。
- 同じキー・同じ要求は、同じサーバー起動中かつ10分以内なら最初の結果を再返却する。加算を二重実行しない。記録はメモリ内に保持する。キーは全クライアント共通の名前空間とし、各クライアントが要求ごとにUUID等の十分に衝突しにくい値を生成する。再送では同じキーを使い、送信元IPには紐付けない。
- 同じキーでパス、メソッド、本文が異なる要求は409。本文はバイト列で比較するため、再送時は空白等も含め同じ本文を使用する。状態変更と再送抑止記録は同じロック内で一括更新する。
- 再送抑止記録は全体で最大10,000件、1件あたり最大16KiB。期限切れを削除し、上限到達時は未期限切れの記録を追い出さず、新規のキー付き操作を429で拒否する。既存キーの再送は受け付ける。
- サーバー再起動で再送抑止記録も消える。再起動後や10分を過ぎての再送は保証対象外とし、外部クライアントは状態確認の後、必要な操作だけを新しい要求として送る。
- 同じ`instanceId`の再送応答より画面の`version`が新しい場合、画面は古い状態で上書きしない。
- `start`と`pause`の状態自体も繰り返しに対して安全にする。resetの古い要求が後から届くことを防ぐため、機器でも再送時は同じキーを使う。
- 設定変更は`If-Match: "<instanceId>:<version>"`を必須とし、欠落は428、不一致は412。GET応答には対応するETagを付ける。画面は再取得して利用者に編集内容の確認を促す。
- コマンドはサーバー受付順に直列実行する。必要なら同じ`If-Match`で競合検出できる。
- 通信タイムアウトで成功不明の場合は状態取得で確認する。自動的に別キーを生成して再実行しない。

### 8.5 エラーとSSE

エラー形式:

```json
{"error":{"code":"INVALID_ARGUMENT","message":"deltaSecondsが範囲外です"}}
```

HTTPコードは400（不正JSON等）、403（操作元制限）、404、409（状態・キー競合）、412、413（本文過大）、422（値不正）、428、429（流量・容量制限）、500（内部エラー）を使う。内部スタックを返さない。

変更APIは送信元IPあたり10件/秒、バースト20件を初期値とする。429には`Retry-After`を付ける。SSE接続はサーバー全体で50本までとし、状態取得は送信元IPあたり別枠で30件/秒を上限にする。送信元IPは直接接続元を用い、任意の転送ヘッダーを信用しない。

SSEは`event: state`でGETと同形式の最新状態を送る。接続直後と1秒ごと、操作成功時に配信する。イベント履歴の再生は行わず、再接続時に最新状態を必ず送る。再接続は1秒から最大10秒の待機へ段階的に増やす。遅い接続は最新状態のみ残し、メモリ上に無制限に蓄積しない。

## 9. 分離ネットワークでの接続

- インターネットから分離された会場内LANで運用する。既定では到達できる端末がすべてのAPIと操作画面を利用できる。ブラウザ操作限定を有効にすると、外部端末は参照APIだけを利用できる。
- 認証、ログイン、APIキー、トークン、セッションCookie、役割別の権限管理は設けない。ブラウザ操作限定は要求ヘッダーによる誤操作防止で、端末の本人性は検証しない。
- 通信はHTTPを使用する。TLS終端、証明書の発行・更新、HTTPSへのリダイレクトは不要。
- 操作URLは `http://<サーバーIP>:8080/`、演台URLは `http://<サーバーIP>:8080/display`。表示URLは固定で、再起動後も変更不要。
- 既定待受は `127.0.0.1:8080`。分離LANで利用するときは起動オプションで会場LAN側のIPまたは`0.0.0.0:8080`を指定する。
- React画面とAPIを同じHTTPサーバーから配信する。初回はクロスオリジンのブラウザ連携を対象とせず、CORS許可ヘッダーは付けない。HTTPを直接送る外部機器・ソフトは利用できる。
- 起動時に操作URL・演台URLを案内する。再起動時は画面・外部機器が状態を再取得して接続を復帰する。

## 10. 設定保存とデータの寿命

タイマーの実行状態と通信管理情報はメモリで管理する。DBは使用しない。再利用する設定だけをJSONファイルへ自動保存する。

| データ | 保持内容・寿命 |
| --- | --- |
| 設定・定型文 | 持ち時間、警告、配色、表示モード、表示言語、点滅、ブラウザ操作限定、定型文。JSONへ保存し再起動後も保持 |
| タイマー | 状態、基準残り時間、単調増加時計の基準点、instanceId、version。サーバー終了まで |
| カンペ | 本文、表示フラグ。サーバー終了まで |
| 暗転 | blackout。サーバー終了まで保持し、次回起動はtrueで初期化 |
| 再送抑止 | 要求キー、要求ハッシュ、結果。10分またはサーバー終了まで |
| Keypad割り当て | JSONへ保存し、全操作画面で共有。Keypad有効状態は各ブラウザのメモリのみ |

ブラウザの再読み込みや端末の通信断だけでは、サーバー上のタイマーは初期化しない。サーバー再起動時は実行状態だけを初期化し、保存済み設定を復元する。失敗した入力は状態も設定ファイルも変更しない。

レート制限用の追跡情報に期限・件数の上限を設ける。再送抑止・SSEの上限と合わせ、通信要求による無制限のメモリ増加を防ぐ。

操作ログは既定でカレントディレクトリの`timeview-operations.jsonl`へJSON Lines形式で追記し、`-audit-log`で変更できる。起動、正常終了、異常終了と変更操作の操作名、成否、HTTPステータス、エラーコード、操作元を記録する。カンペ本文、設定値、要求本文、毎秒の状態配信は記録しない。各行は追記後に同期し、異常終了直前までの記録を優先する。ログローテーションは初期範囲外とする。

設定ファイルは既定でカレントディレクトリの`timeview-config.json`とし、`-config`で変更できる。初回起動時に既定値で生成する。書き込みは同じディレクトリの一時ファイルを同期後に置換し、途中までのJSONを残さない。未知フィールド、不正値、未対応バージョンは起動時に拒否し、既定値で黙って上書きしない。

## 13. 実装順序と成果物

1. Taskfile.ymlとGo／Reactの開発環境を整え、Goのメモリ内タイマー・JSON設定保存・単一タイマーAPIを作り、時間計算と再送抑止を検証する。
2. Reactの操作画面と演台画面、SSE同期、カンペ、画面暗転を実装する。
3. Keypad割り当て、外部API連携例を仕上げる。
4. 再接続・再起動・性能・OS別の試験を行い、Windows・macOS・Linux向け配布物と操作手順を整える。

成果物は、Go／Reactソース、Taskfile.yml、OS／CPU別の実行ファイル、JSON設定ファイル、OpenAPI形式のAPI定義、API操作例、セットアップ・再起動手順、受入試験結果とする。

### 13.1 Taskによる開発・ビルド

リポジトリ直下に`Taskfile.yml`を配置し、スキーマは`version: '3'`を使用する。Taskの定義形式は[公式ガイド](https://taskfile.dev/docs/guide)に従う。Task本体のバージョンは実装開始時に固定し、開発手順に記載する。

| コマンド | 役割 |
| --- | --- |
| `task --list` | 利用可能なタスクと説明を表示 |
| `task setup` | Go依存とフロント依存をロックファイルに従って取得 |
| `task dev:backend` | 開発用Goサーバーを起動 |
| `task dev:frontend` | Vite開発サーバーを起動。API・SSEはGoへプロキシ |
| `task fmt` | Go・フロントのコードを整形 |
| `task lint` | Goの静的検査、TypeScriptの型検査、フロントのlint |
| `task test` | Go・フロントの自動テストを実行して終了 |
| `task build` | Reactをビルドして埋め込み、実行中のOS／CPU向けGo実行ファイルを生成 |
| `task release` | Reactをビルド後、11.1の全OS／CPU向け実行ファイルを生成 |

開発時は別ターミナルで`task dev:backend`と`task dev:frontend`を実行する。Go embedの対象が必要な場合は、バックエンド起動前にフロント成果物を準備する。実行ファイルの出力先は`dist/<os>-<arch>/`とする。

Taskの`dir`・`env`等で作業ディレクトリとビルド環境変数を指定し、Windows専用コマンドやUnix専用の外部コマンドへの依存を避ける。フロントのビルド完了後にGoをビルドする順序を保証し、途中の失敗は非ゼロ終了として伝える。Windows・macOS・Linuxで同じタスク名を使用する。

開発・ビルド環境にはGo、Node.jsとパッケージマネージャー、Taskを用意する。依存取得は開発環境で事前に行い、上映会場では配布済み実行ファイルだけで動作させる。会場での実行にTaskのインストールは不要。

受入時は各開発OSで`task lint`・`task test`・`task build`を確認し、`task release`が指定した5種類の実行ファイルを生成することを確認する。各成果物の実行確認は11.1に従う。

## 14. 実装前に調整できる項目

現時点では次の仮定で仕様を成立させている。具体的な機器や運用に合わせて変更できる。

| 項目 | 本案の前提 | 変更による影響 |
| --- | --- | --- |
| Keypad実機 | 標準USBテンキー | 専用HID・シリアル機器なら別途接続方式が必要 |
| 操作の常駐性 | 前面の操作画面で入力、常時制御はHTTP | バックグラウンドでキー取得するならネイティブ補助アプリが必要 |
| 設置 | Windows・macOS・LinuxのPC・オフラインの分離LAN | 会場のアドレス構成に合わせてHTTP待受先を指定 |
| 時間切れ | マイナス表示で継続 | 0固定や自動停止を希望する場合は状態・表示仕様を変更 |
| 状態の寿命 | 設定はJSONへ保存。実行状態はメモリのみ | 実行中タイマーの復元が必要な場合は別途設計 |
| UI言語 | 日本語／英語 | 設定画面で切り替え、JSONへ保存して全画面へ同期 |
| デザイン | 暗色・大きな時間表示 | 色、ロゴ、レイアウトは画面実装時に調整 |
