# HTTP API・SSE仕様

[仕様書の入口へ戻る](../SPECIFICATION.md)。ベースパスは`/api/v1`。機械可読な契約は[OpenAPI](../openapi.json)、実行例は[開発ガイド](../DEVELOPMENT.md#api利用例)を参照する。

## 外部API仕様

### 共通規則

- ベースパス: `/api/v1`。JSON、UTF-8。
- すべてのAPIは認証なしのHTTPで利用する。Authorizationヘッダー、APIキー、Cookieは不要。
- 変更処理はPOST／PATCH／PUT／DELETEを使う。GETでは状態を変更しない。
- 秒・ミリ秒の単位をフィールド名で明示する。
- 未知フィールド、型違い、範囲外の値は拒否する。リクエスト本文上限は通常16KiB。設定一括読込・検証の`/timer/config`と`/timer/config/validate`は64KiB。
- 時間差で残り時間が変わっても`version`は増やさず、状態・設定の変更時に増やす。起動時は0から開始する。
- 部分的に変更して失敗することはない。各リクエストは原子的に実行する。
- 任意の`X-Timeview-Instance`ヘッダーに取得済みの`instanceId`を指定できる。再起動で不一致になった場合は409とし、操作しない。Reactからの変更要求には必ず付ける。
- `browserOnly=true`ではGETとSSEを引き続き公開し、変更要求だけを同一オリジンのTimeView操作画面とKeypadに限定する。画面は`X-Timeview-Client: browser`を付け、サーバーはブラウザが付与する`Sec-Fetch-Site: same-origin`との両方を確認する。条件を満たさない変更要求は403 `BROWSER_ONLY`とし、状態や再送記録を変更しない。
- 操作元制限は分離LAN内の誤操作防止であり、認証ではない。HTTPクライアントは同じヘッダーを模倣できるため、悪意ある端末への防御には使用しない。操作画面を利用できない場合は、サーバー停止中にJSON設定の`browserOnly`を`false`へ戻す。

### エンドポイント

| Method | パス | 用途 |
| --- | --- | --- |
| GET | `/health` | プロセス稼働確認 |
| GET / PATCH | `/timer` | 状態取得／設定変更 |
| POST | `/timer/commands` | start、pause、reset、adjust |
| PUT | `/timer/blackout` | `{"enabled":true}`で暗転、`{"enabled":false}`で解除 |
| PUT | `/timer/message` | 本文と表示フラグの更新 |
| DELETE | `/timer/message` | カンペ消去 |
| GET / PUT | `/timer/presets` | 定型文一覧／一括更新 |
| GET / PUT | `/timer/bindings` | Keypad・MIDI割り当て一覧／一括更新 |
| GET / PATCH | `/timer/config` | 設定JSON取得／一括適用 |
| POST | `/timer/config/validate` | 設定JSONの検証のみ |
| GET | `/timer/displays` | 演台接続一覧 |
| PUT / DELETE | `/timer/displays/{id}` | 応答報告／応答なし記録の削除 |
| PUT | `/timer/displays/{id}/name` | 演台名の変更・解除 |
| GET | `/timer/events` | 状態・任意の演台一覧／ログのSSE配信 |
| GET | `/logs` | 操作・プロセスログの最新500件 |

操作画面と演台画面は同じ状態取得APIとSSEを利用する。演台画面には操作UIを設けない。通常の変更APIは操作元制限が有効ならブラウザ要求情報を確認する。演台の応答報告・名前変更・記録削除は設定にかかわらず同一オリジンのブラウザに限定する。タイマーの作成・削除APIは設けず、起動時から1つ存在する。

### コマンド例

```http
POST /api/v1/timer/commands
Content-Type: application/json
Idempotency-Key: <UNIQUE_REQUEST_ID>

{"command":"adjust","deltaSeconds":60}
```

開始・一時停止・リセットは、それぞれ `{"command":"start"}`、`{"command":"pause"}`、`{"command":"reset"}` を送る。

暗転は`PUT /api/v1/timer/blackout`へ`{"enabled":true}`、解除は`{"enabled":false}`を送る。`enabled`は必須のbooleanで、省略・null・文字列は422。同じ値を繰り返し指定しても反転せず、変更がなければ`version`を増やさない。成功時は200と最新状態を返し、変更時はSSEへ即時配信する。`Idempotency-Key`と任意の`If-Match`は共通規則を適用する。`PATCH /timer`での暗転変更は受け付けず、この専用APIへ集約する。

成功時は200と最新状態を返す。例:

```json
{
  "instanceId": "boot_abc123",
  "version": 12,
  "state": "running",
  "durationSeconds": 600,
  "remainingMs": 359800,
  "serverTimeMs": 1789776000000,
  "warning1Seconds": 180,
  "warning2Seconds": 60,
  "message": {"text": "まとめをお願いします", "visible": true},
  "displayMode": "timer_and_message",
  "language": "ja",
  "logLevel": "info",
  "blackout": true
}
```

### 再送・競合

- `adjust`では`Idempotency-Key`を必須とし、通常の変更APIで利用可能にする。UIはこれらの変更操作に付ける。演台の応答報告は対象外で、同じIDの記録を更新する。
- 同じキー・同じ要求は、同じサーバー起動中かつ10分以内なら最初の結果を再返却する。加算を二重実行しない。記録はメモリ内に保持する。キーは全クライアント共通の名前空間とし、各クライアントが要求ごとにUUID等の十分に衝突しにくい値を生成する。再送では同じキーを使い、送信元IPには紐付けない。
- 同じキーでパス、メソッド、本文が異なる要求は409。本文はバイト列で比較するため、再送時は空白等も含め同じ本文を使用する。状態変更と再送抑止記録は同じロック内で一括更新する。
- 再送抑止記録は全体で最大10,000件、1件あたり最大16KiB。期限切れを削除し、上限到達時は未期限切れの記録を追い出さず、新規のキー付き操作を429で拒否する。既存キーの再送は受け付ける。
- サーバー再起動で再送抑止記録も消える。再起動後や10分を過ぎての再送は保証対象外とし、外部クライアントは状態確認の後、必要な操作だけを新しい要求として送る。
- 同じ`instanceId`の再送応答より画面の`version`が新しい場合、画面は古い状態で上書きしない。
- `start`と`pause`の状態自体も繰り返しに対して安全にする。resetの古い要求が後から届くことを防ぐため、機器でも再送時は同じキーを使う。
- `PATCH /timer`と`PATCH /timer/config`は`If-Match: "<instanceId>:<version>"`を必須とし、欠落は428、不一致は412。GET応答には対応するETagを付ける。画面は再取得して利用者に編集内容の確認を促す。
- コマンドはサーバー受付順に直列実行する。必要なら同じ`If-Match`で競合検出できる。
- 通信タイムアウトで成功不明の場合は状態取得で確認する。自動的に別キーを生成して再実行しない。

### エラーとSSE

エラー形式:

```json
{"error":{"code":"INVALID_ARGUMENT","message":"deltaSecondsが範囲外です"}}
```

HTTPコードは400（不正JSON等）、403（操作元制限）、404、409（状態・キー競合）、412、413（本文過大）、422（値不正）、428、429（流量・容量制限）、500（内部エラー）を使う。内部スタックを返さない。

変更APIは送信元IPあたり10件/秒、バースト20件を初期値とする。429には`Retry-After`を付ける。SSE接続はサーバー全体で50本までとし、状態取得は送信元IPあたり別枠で30件/秒を上限にする。送信元IPは直接接続元を用い、任意の転送ヘッダーを信用しない。

SSEは`event: state`でGETと同形式の最新状態を送る。接続直後と1秒ごと、操作成功時に配信する。イベント履歴の再生は行わず、再接続時に最新状態を必ず送る。再接続は1秒から最大10秒の待機へ段階的に増やす。遅い接続は最新状態のみ残し、メモリ上に無制限に蓄積しない。

### UIなしリモコン

別PC向けに `timeview-remote` 実行ファイルを配布する。既存HTTP APIを利用し、状態確認、開始、一時停止、リセット、加減算、暗転、暗転解除、カンペ表示・非表示・消去・本文送信、定型文送信を1コマンドで実行する。操作を省略した場合は`listen`を実行する。Windows、macOS、Linux（X11）版の`listen`は起動時に`GET /timer/bindings`から割り当てを取得し、OS全体のキー入力とMIDI入力を対応操作へ変換する。割り当て変更と機器の抜き差しは再起動時に反映する。認証情報は保持せず、分離LAN内でサーバーURLを明示して使用する。ブラウザ操作限定が有効な場合はAPIの403をそのまま日本語で表示する。

## 設定のバックアップAPI

設定画面末尾からJSON設定を書き出し・読み込める。形式は既存の設定ファイル（version: 1）と共通で、タイマー設定・定型文・Keypad/MIDI割り当てのみを含む。計測状態・残り時間・暗転・現在のカンペは含まない。

- `GET /api/v1/timer/config`: 設定JSONとETagを取得する。
- `POST /api/v1/timer/config/validate`: 本文を既存の設定検証で確認する。設定・実行状態・versionを変更しない。
- `PATCH /api/v1/timer/config`: If-Match必須。待機中のみ、検証と保存に成功した全設定を一括適用する。暗転・現在のカンペ・instanceIdを保持する。
- 読込と検証の本文上限は64KiB。既存のブラウザ操作限定・レート制限・冪等性チェックを適用する。不正な値・未知の項目・未対応バージョンを拒否し、保存失敗時も既存設定を保持する。

## 演台ページの接続確認

通常操作画面の演台プレビュー下とタッチ操作画面に、応答している演台ページ数と応答なしのページ数を表示する。詳細でページごとのランダムID（先頭8桁）・応答状態・最終応答時刻を確認できる。物理端末数ではなく `/display` ページ数であり、操作画面・タッチ画面・プレビューは含めない。映像出力やモニターの電源状態は検証しない。

- 演台はSSEで状態を受信して接続中と判定されている間、5秒ごとに応答を送る。ページのマウントごとに新しいIDを作成し、再読込前の記録は期限まで残る。
- `PUT /api/v1/timer/displays/{id}`: 同一オリジンのブラウザ限定。IDは32桁の16進数。本文に現在の `instanceId` と受信済み `version` を指定し、成功は204。本文上限16KiB。古い起動IDは409、未来／負のversionや不正な本文は拒否する。既存のレート制限を適用する。応答記録はタイマー・設定・ETag・操作ログを変更しない。
- `GET /api/v1/timer/displays`: `instanceId` と `displays` 配列（`id`, 任意の`name`, `lastSeenMs`, `version`, `online`）を返す。15秒以上応答がなければ応答なし、30分以上で記録を除去する。操作画面はSSEの `displays` イベントで受信し、接続断や受信前は確認不能と表示する。
- 記録はメモリのみで最大50件。上限時は最も古い応答なしの記録を置換し、全件応答中なら429。サーバー再起動時は空にする。遅れて届いた応答で受信済みversionを巻き戻さない。
- `PUT /api/v1/timer/displays/{id}/name` は同一オリジンのブラウザ限定で、本文`{"name":"控室"}`を受け付ける。名前は改行なし40 Unicodeコードポイント以内、前後の空白を除去し、空欄で解除する。不正な名前は422。名前は改行なし40 Unicodeコードポイント以内、前後の空白を除去し、空欄で解除する。不正な名前は422。名前は改行なし40 Unicodeコードポイント以内、前後の空白を除去し、空欄で解除する。不正な名前は422。存在しない記録は404。通常の変更APIの保護・冪等キーを適用し、200でタイマー状態を返す。名前の変更はタイマー・ETag・設定を変更せず、GET一覧とSSEの演台記録に任意の`name`を含めて共有する。
- `DELETE /api/v1/timer/displays/{id}` は同一オリジンのブラウザ限定。15秒以上応答のない記録を削除し、存在しない記録は成功、応答中は409。通常の変更APIのサイズ・レート制限、起動ID・任意のETagチェック、冪等キーを適用する。200でタイマー状態を返すが、状態・ETag・設定は変更しない。削除結果はSSEで共有し、後続の応答があれば記録を再作成する。

## 操作データのSSE同期

`GET /api/v1/timer/events` の既存 `state` イベントに、任意の `topics` クエリで `displays`・`logs` を追加購読できる（カンマ区切り）。未知の対象は422。省略時は従来どおりタイマー状態のみ配信する。既存の全体50接続上限・遅い接続の送信期限・最新状態への通知集約を維持する。

- 通常操作画面は `?topics=displays,logs`、タッチ操作画面は `?topics=displays` を使い、各画面1本のSSE接続を共有する。演台画面は追加購読しない。演台一覧のポーリングとログの手動更新は廃止する。タイマー状態の定期GETも廃止し、初回・操作失敗時の取得だけを残す。
- `displays` イベントの本文は `{instanceId, displays}`。初回／再接続と、応答受信・応答なしへの遷移・保持期限による削除で最新一覧を送る。応答なし・期限切れはサーバーの既存1秒周期で検出する。内容に変更がなければ送らない。
- `logs` イベントの本文は `{instanceId, entries}`。初回／再接続と操作ログの保存成功後に、新しい順の最新500件を送る。成功したスナップショットは同じログ世代の購読者間で共有し、各接続によるファイルの再読込を避ける。読込失敗は `{instanceId, entries:null, error:"操作ログを取得できませんでした"}` とし、次の周期で再試行する。
- 初回／再接続時は必ず `state` を先に送り、追加購読の最新一覧も送り直す。イベントの差分履歴再生は不要とし、切断中のログは最新500件の範囲で復旧する。各一覧の `instanceId` が現在の状態と異なる場合、クライアントは破棄する。
- 通信断・サーバー再起動時はクライアントの追加データを無効にし、古い一覧を現在の情報として扱わない。stateを5秒受信できなければ接続を閉じて再接続し、再接続待機は1秒から最大10秒まで増やす。
- `GET /api/v1/logs` と `GET /api/v1/timer/displays` は外部利用向けに維持する。演台からサーバーへの5秒ごとの応答送信も維持する。

タッチ操作画面は通常操作画面と同じ終了予定時刻・演台一覧コンポーネントを使用する。接続詳細は折りたたみ表示とし、通常のタイマー操作を圧迫しない。
