# TimeView 運用ガイド

会場で操作する方向けの手順です。初回の起動は[README](../README.md#まず使ってみる)、動作の詳細は[仕様書](SPECIFICATION.md)を参照してください。

## 上映・講演前に確認する

1. サーバーPCを電源へ接続し、運用中にスリープしない設定にする。演台PCの画面消灯やスリープも確認する。
2. 会場LANでサーバー・操作端末・演台端末を接続し、各端末から操作URL・演台URLを開く。
3. 「設定・外部連携」で持ち時間、警告、配色、表示モード、定型文を確認して反映する。
4. 演台を全画面にし、暗転解除・カンペ送信・警告色を実際のモニター／プロジェクターで確認する。
5. 使用するKeypad・MIDI・リモコンから実際に操作し、意図した操作だけが反映されることを確認する。
6. リハーサルで動かしたタイマーをリセットし、カンペの消去・表示状態と暗転を本番の開始状態へ揃える。

暗転が制御する範囲は演台ページです。OS通知やブラウザUI、プロジェクター本体のシャッターは制御しません。画面の応答と、会場で見える映像は両方確認してください。

## 普段の操作

通常画面ではタイマー操作と演台プレビュー、カンペ、Keypad・MIDIを扱います。司会者がタッチする端末では`/touch`を開きます。自由文の入力や設定変更は通常画面で行います。

- 「開始」は待機中から開始し、一時停止中なら再開する。「一時停止」は現在の残り時間で止める。
- 「±1分」は残り時間だけを変更する。「リセット」は計測を止め、設定済みの持ち時間へ戻す。カンペ・暗転はそのまま残る。
- 終了予定時刻は待機中に「今開始した場合」、一時停止中に「今再開した場合」を示す。計測中は加減算に追従し、超過中は0に到達した時刻を示す。日付をまたぐ場合は月日も表示する。
- カンペの入力欄は下書き。「送信」で演台へ反映する。非表示は本文を保持し、再表示できる。消去は本文を削除する。定型文は押すと即時送信する。
- 暗転中も計測は続く。解除すると、その時点の時間とカンペが表示される。

## 設定を変更する

設定は「タイマー・表示」「定型文」「入力・外部連携」「設定のバックアップ」に分かれています。持ち時間の変更は待機中のみです。日本語・英語を切り替えても、操作失敗のメッセージは日本語で表示します。

タイマー設定は「設定を反映」、定型文は保存ボタンを押して適用します。Keypad・MIDIの割り当ては登録成功時に保存します。未保存の設定・定型文は、通常操作・設定・ログの切り替えでは保持しますが、再読み込みやタッチ画面への移動では失われます。

別端末の操作などで設定が競合した場合は、入力内容を控えてから「最新の設定を読み直す」を押し、再編集してください。

### 設定のバックアップと復元

1. 「設定のバックアップ」を開き、書き出しボタンで`timeview-settings.json`を保存する。
2. 復元先を待機状態にし、必要なら復元前の設定も書き出す。
3. 読み込むJSONファイルを選ぶ。サーバーで検証された変更項目を展開し、現在の値と読込後の値を確認する。
4. 適用ボタンで一括反映する。取りやめる場合は取消する。

対象はタイマー設定・定型文・Keypad／MIDI割り当てです。実行状態、残り時間、暗転、現在のカンペ、演台名、操作ログは含みません。読み込みは待機中・接続中に限り、ファイルは64KiB以内です。検証後に他の操作が入って競合した場合は、再度読み込んで差分を確認します。

読み込みは設定を置き換えますが、現在の暗転・カンペは維持します。不正なJSON、未知の項目、未対応バージョン、保存失敗では既存設定を保持します。

### 保存先と手作業での編集

既定では起動フォルダーへ`timeview-config.json`と`timeview-operations.jsonl`を作成します。別の場所を使う場合、親フォルダーを先に作成して指定してください。

```powershell
.\timeview.exe -config C:\TimeView\config.json -audit-log C:\TimeView\operations.jsonl
```

設定JSONを手作業で編集するときは、サーバーを停止してファイルをコピーしてから変更し、再起動します。不明な項目・不正値・未対応バージョンがあると起動を中止します。原因を修正するか、控えておいた有効な設定へ戻してください。

サーバーの再起動では保存済みの設定を復元し、タイマーは待機・持ち時間全量・暗転ON・カンペなしになります。

## 演台の接続と名前

通常画面のプレビュー下、またはタッチ画面の「演台接続」を開きます。数えているのは`/display`ページです。同じPCで2ページ開けば2画面として記録します。

| 状態 | 意味 |
| --- | --- |
| 応答あり | ページが状態を受信し、最近の応答をサーバーへ送っている |
| 応答なし | 15秒以上応答がない。閉じたページや通信断も含む |
| 確認不能 | 操作画面が未接続、または一覧の受信前。現在の応答状態を判断できない |

演台は接続中に5秒ごとに応答し、一覧はSSEで自動更新します。記録は最終応答から30分で除去されます。これは映像出力・モニター電源・投影内容の保証ではありません。

### 名前を付ける

名前横の鉛筆アイコンを押し、入力して保存します。名前は改行なし40文字以内です。前後の空白は除去され、空欄で保存すると解除します。取消なら変更しません。名前と短縮IDは他の操作画面にも共有されます。

名前は接続記録に対する一時的なメモです。同じIDの通信復旧では保持しますが、**演台ページの再読み込みは新IDになるため引き継ぎません**。サーバー再起動、記録の期限切れ、一覧からの削除でも解除されます。

### 応答なしの記録を削除する

対象行の右端にあるごみ箱アイコンを押し、名前・IDを確認して削除します。演台のブラウザを閉じたり、表示を停止したりする操作ではありません。

応答中の記録は削除できません。確認中に応答が戻った場合も削除を拒否します。削除後に同じページから応答が届けば、名前なしで再び一覧へ追加されます。

## KeypadとMIDI

### ブラウザのKeypad

操作画面でKeypadをONにし、その画面を前面にして操作します。画面切り替え、タブ非表示、フォーカス喪失、通信断ではOFFへ戻るため、必要な場合は再度有効にしてください。テキスト入力中はタイマー操作を実行しません。

| 既定キー | 操作 |
| --- | --- |
| テンキーEnter / 小数点 | 開始・再開 / 一時停止 |
| テンキー＋ / − | +60秒 / −60秒 |
| Ctrl + テンキー0 | リセット |
| Ctrl + テンキー− / ＋ | 暗転 / 暗転解除 |
| テンキー1～9 | 定型文を即時送信 |
| テンキー0 / × / ÷ | カンペ非表示 / 再表示 / 消去 |

設定の「入力・外部連携」で対象のキーを選び、新しいキーを押すと登録できます。Escapeで入力待機を解除します。欄を折りたたんでもキー・MIDIの入力待機を解除します。割り当ては保存しますが、有効状態は保存しません。

### ブラウザのMIDI

Web MIDI対応のChrome／Edgeを使い、コントローラーをブラウザを開くPCへ接続します。安全なコンテキストが必要なため、基本はサーバーPCの`http://127.0.0.1:8080/`を使います。

「入力・外部連携」で対象操作の「MIDI Learn」を押し、パッドやボタンからNote OnまたはControl Changeを送って登録します。通常画面のMIDI有効状態を確認して使います。割り当てはJSONへ保存され、同じ入力の重複割り当ては拒否します。押下中の反復は1操作として扱います。

## UIなしリモコン

同梱の`timeview-remote`（Windowsは`timeview-remote.exe`）を操作用PCへ置くと、ブラウザなしでHTTP操作やKeypad・MIDIの常時監視ができます。TimeViewの「ブラウザからの操作だけを許可」はOFFにします。

```sh
timeview-remote -server http://192.168.1.10:8080 status
timeview-remote -server http://192.168.1.10:8080 start
timeview-remote -server http://192.168.1.10:8080 add 60
timeview-remote -server http://192.168.1.10:8080 message "残り5分です"
# 操作を省略するとlisten。終了はCtrl+C
timeview-remote -server http://192.168.1.10:8080
```

PowerShellで起動フォルダーにあるファイルを使う場合は`.\timeview-remote.exe`のように指定します。

操作は`listen`、`status`、`start`、`pause`、`reset`、`add [秒]`、`subtract [秒]`、`blackout`、`reveal`、`hide`、`show`、`clear`、`message <本文>`、`preset <1～9>`です。終了コード0は成功、通信・入力・APIエラーは日本語で標準エラー出力へ表示します。

`listen`は起動時にサーバーから割り当てを取得します。割り当て変更やMIDI機器の抜き差し後は再起動してください。OS全体のキーを監視するため、別アプリを操作中でも反応します。

- macOSではアクセシビリティの入力監視許可が必要です。
- LinuxはX11セッションで使用します。Waylandネイティブ環境は対象外です。最小構成ではX11、Xtst、X11-xcb、xcb-xkb、xkbcommon、ALSAのランタイムライブラリをOSのパッケージ管理から追加します。

## 操作ログ

`/logs`では最新500件を新しい順に表示し、SSEで自動更新します。カンペ本文・設定値・要求本文は記録しません。切断中の記録は再接続時に最新500件の範囲で表示します。

ファイルの操作ログは起動・終了・異常終了・変更操作の成否をJSON Lines形式で追記します。画面の500件上限はファイルの保存件数を制限しません。自動ローテーションはないため、継続運用では容量を確認し、サーバー停止中にログを退避してください。

コンソールのシステムログは別の出力です。設定画面で`DEBUG`、`INFO`、`WARN`、`ERROR`を選ぶと、その場で出力レベルが変わり、設定へ保存します。

## 困ったとき

| 状況 | 確認・対処 |
| --- | --- |
| 演台が真っ黒 | 起動時は暗転ON。操作画面の接続と暗転状態を確認し、表示する場合は暗転解除する |
| 別端末から開けない | サーバーの起動、LAN側IP、`-listen`、会場LAN、ファイアウォールを順に確認する |
| 接続が切れた | 接続表示が復帰するのを待ち、実際の演台を確認する。未完了操作を自動再送しないため、現在の状態を見て必要な操作だけやり直す |
| 演台だけが応答なし | 対象ページと端末のネットワーク・スリープを確認する。古い記録を消しても接続は修復しない |
| サーバー再起動の通知 | タイマーは初期化済み。持ち時間・カンペ・暗転を確認し、必要な内容を設定してから再開する |
| 設定が競合 | 編集内容を控え、最新設定を読み直して再編集する。バックアップなら再読込して差分確認する |
| 設定を保存できない | 保存先の親フォルダー、書込権限、ディスク容量、表示されたエラーを確認する |
| 外部API／リモコンが403 | 「ブラウザからの操作だけを許可」を確認する。必要な場合は設定画面でOFFにする |
| MIDIが使えない | 対応ブラウザ、`127.0.0.1`での接続、許可、機器の接続先、有効状態と割り当てを確認する |
| スリープから復帰した | 状態の再同期と演台の実表示を確認する。スリープ中の同期は保証しない |

操作画面が使えずブラウザ操作限定を解除する場合は、サーバーを停止し、設定JSONの`timer.browserOnly`を`false`へ変更して再起動します。

## Dockerの停止とデータ

```sh
docker compose down
```

通常の`down`では名前付きボリューム`timeview-data`を残します。設定とログはコンテナ内の`/data`へ保存されます。`docker compose down -v`はボリュームも削除するため、設定・ログを残す運用では使用しません。
